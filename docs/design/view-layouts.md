## 1. 背景

1. **两个页面只有分页表格，看图挑选不趁手**：图组管理（`ProcessPage.vue`）一屏几十行文字看不到图；图库（`LibraryPage.vue`）虽有 90px 预览列，但整体按表格排，挑图要来回扫行。
2. **平铺不是「换个样式的表格」，而是相册式的两级结构**：一级看分组、点开看这个分组里的图。两页的「分组」含义不同——图组页的分组是图组本身，图库页的分组是角色（见 3.1）。
3. **图库页的封面现成**：每行都带 `selectedFileThumbnail`（`image_file.thumbnail` 的 BLOB 经 `shapeRow` 转成 data URL）。**图组页没有封面**，要么占位、要么按组取一张代表图——取代表图必须是**一条分组查询**，不能逐行查。
4. **数据量可以很大，所以平铺不分页**：沿用表格的分页会把「相册」切碎；浏览器与手机相册都是滚到底。因此平铺靠**懒加载 + 虚拟滚动**支撑。
5. **现状是「全量取回 + 内存分页」，重的那部分必须改**：`LibraryPage.loadData()` 调无参的 `getAllProcessedImages()`（`db.ts:740` 由 `SELECT_PROCESSED_VIEW_BASE`（`sql.ts:173`）起头，**没有 LIMIT**，且每一行的缩略图 BLOB 都被 `shapeRow` 转成 data URL），筛选、排序、分页全在渲染进程 computed 里做（`LibraryPage.vue:257`~`294`）。实测 4175 行：查询 48ms、含 base64 约 77ms、缩略图字节 11.7MB（字符串约 15MB）。同一笔债还有第二处：打开查看器时 `openViewer`（`LibraryPage.vue:314`）把整个列表（含缩略图）塞进 IPC。
6. **原稿写的页面不对**：本路线图第一稿按「来源页 + 角色页」写（还把来源页称作「图库页」），与实际要做的图组页 + 图库页不是同一对（见 1.1）。

## 2. 目标与非目标

**目标**

1. 两个页面保留现有的分页表格，并在**页脚左侧**提供一个图标按钮，在「列表 / 平铺」之间切换（只有两个视图，一个按钮即可，像操作系统的文件管理器），选择要记住；**切视图回到第一页 / 顶部**。
2. 平铺是相册式两级结构：一级是分组卡片（图组页＝图组，图库页＝角色），**单击卡片在它所在行的下方展开**该分组的图片；再点收起；**一次只展开一个**。
3. 平铺**不分页**：用懒加载 + 虚拟滚动支撑大数据量；**带缩略图的重数据与一级索引行一律分片取**（见 3.8），不再全量取回。
4. 平铺项尺寸固定：封面用现有的缩略图尺寸 100×100（`THUMBNAIL_SIZE`）；布局与窗口化按「尺寸将来可变」设计（自适应列数，见 3.3）。
5. **选中在两个视图、翻页、筛选、排序之间都保留**（表格用 `reserve-selection`），只有显式取消才清空。
6. 没有封面时先用占位图标；封面的统一视觉（例如多张叠放）另作安排（见 §8）。

**非目标**

- 不改数据模型（不加表、不加列）；
- 不重做表格的观感；
- 首版不做拼音排序键、不做封面叠放、不做平铺项尺寸调节、不做键盘可达性与辅助技术适配；
- 不把视图偏好写进数据库（放 `localStorage`，将来迁进设置页）。

## 3. 设计

### 3.1 两级结构与两页的分组含义

| 页面 | 一级＝分组 | 二级＝展开面板里的图片 |
|---|---|---|
| 图组管理（`ProcessPage`） | 图组（现在表格的每一行，轻量列） | 该图组的图片文件（含缩略图，展开时**分片**取） |
| 图库（`LibraryPage`） | **角色**（`character` 表，轻量列） | 该角色下的**已选定图**（`processed_image`，含缩略图，**分片**取） |

- 展开面板插在「该卡片所在那一行」的下方、整行宽；一级网格用它上方的卡片排版不变。
- **一次只展开一个**：展开另一个时自动收起上一个。

### 3.2 点击与选中的分工（已定）

| 动作 | 图组管理 | 图库 |
|---|---|---|
| 单击卡片 | 展开 / 收起该分组 | 同左 |
| 双击卡片 | 不做（第一次单击已经展开，双击只能靠延迟判定，手感差） | 同左 |
| 卡片上的复选框 | 勾选该图组（批量处理 / 标记排除的单位＝图组） | **三态**：全选该角色下全部图片 / 部分选中 / 未选；勾选卡片＝选中它下面所有图片 |
| 展开面板里的图片 | **不提供勾选**（图片级在图组页没有批量意义） | 单击＝打开图片查看器；勾选框**悬停时出现**，该项已被勾选（或所属分组有勾选）时**常显** |
| 打开整个分组 | 卡片右下角的图标按钮（悬停出现）+ 右键菜单；展开面板里的「打开全部」 | 同左 |

- **选中是持久的**：翻页、改筛选、改排序、切视图都不清空；批量按钮（图库页的删除选中 / 导出、图组页的批量处理 / 标记排除）始终看 `selectedIds`。表格侧加 `reserve-selection`（`el-table` 需要 `row-key`，已有）。

### 3.3 懒加载、自适应网格与「行窗口化」

- **平铺不分页**：一级与二级共用一个滚动容器；二级只有展开某个分组时才取该组的图片，并且**面板自己是一个有最大高度的可滚动区域**（高度自适应、**只设上限不设下限**），面板内部同样做虚拟滚动。
- **「行窗口化」是什么**：虚拟滚动的一种具体做法——把卡片按*当前列数*切成一行行的数组（第 1 行是卡片 1..n，第 2 行是 n+1..2n……），只把视口附近的那几行真正挂到 DOM 上，滚过去就换内容；滚动条高度用「总行数 × 行高」撑出来，所以看起来像全都在。按行算实现简单，也最容易和自适应列数配合。
- **首版的范围**：一级（卡片）做行窗口化；二级面板有自己的最大高度与滚动条，按 60 张一批续取就够（不另做一套窗口化），等基础形态稳定后再补。
- **列数不写死**：网格用自适应列数（`auto-fill` + `minmax(...)`），窗口化按**实测**的容器宽度与列数计算（`ResizeObserver`）；将来把卡片尺寸做成可调时，只需要改「卡片宽高」这一个来源。
- 请求要**去重 + 过期响应丢弃**（快速滚动与快速展开时会并发）。

### 3.4 封面

- 尺寸：100×100（与缩略图常量一致），`object-fit: cover`。
- 图库页与图组页都只用**一条按分组取代表图的查询**（只查当前可见分组的 id，返回 `{ groupId: dataUrl }`），不逐行查。
- 没有缩略图时先用占位图标（统一视觉见 §8）。

### 3.5 视图切换按钮

- 位置：**页脚那一行的左下角**（现在分页器占右下、左侧空着），一个图标按钮，点一下在两种视图之间切换；tooltip 显示「切到平铺 / 切到列表」。
- 表格视图下分页器照旧在右下；**平铺视图下隐藏分页器**（它不分页），按钮仍在左下角。
- **切视图回到第一页 / 顶部**，筛选与排序保持。
- 偏好存 `localStorage`：`view-mode:process` / `view-mode:library`；读不到就退回列表。

### 3.6 与图片查看器的接线

- **图组页**：点展开面板里的图片 → 图片查看器打开**该图组的图片**并定位到这一张；分组上的「打开全部」走同一个列表。
- **图库页**：点图片 → 图片查看器打开**当前筛选结果**并定位到这一张。
- **载荷改造**：现在 `openViewer`（`LibraryPage.vue:314`）把整个列表（`sortedImages`，含全部缩略图，实测十几 MB）塞进 `VIEWER_OPEN` 一次发给查看器窗口。改成只传「筛选条件 + 起始那一张的 id」，查看器自己按分片向主进程要缩略图与相邻几张（**已定：本次做**）。
- **图组页在平铺下不再提供「查看文件」**：展开本身就能看到图片列表；由此产生的「手动确认选图」缺口记在 §8（表格视图仍有该入口）。

### 3.7 筛选与排序

- **语义不变**：图组页筛选作用于图组；图库页筛选作用于单个图片（与脚本列表一致），展示仍按角色分组，**筛选后为空的分组隐藏**；**筛选条件一变就回到第一页**；输入加约 200ms 防抖（现在是输入即过滤，下推后会变成每次按键一次查询）。
- **排序的硬限制（实测）**：SQLite 内核只有码点序——`PRAGMA compile_options` 里只有 `ENABLE_FTS3` / `ENABLE_FTS3_PARENTHESIS` / `ENABLE_FTS5`，没有任何语言感知的排序规则：试 `COLLATE pinyin` / `COLLATE zh` 都报 `no such collation sequence`（只有 `NOCASE` 可用），`node:sqlite` 也没有 `createCollation`。所以**语言感知排序在数据库侧做不到**；JS 的 `localeCompare` 做得到，但它要求全局排序，与分片天然冲突。
- **方案（已定，路线 A）**：纯 JS 拼音库 + **每字段一个排序键列**——写入 / 改名时只算这一行，SQL 按 `ORDER BY <排序键>, id` 排，一级二级都能分片，将来还能顺带做拼音 / 首字母搜索。规则与可插拔的模块见 §9.2，为什么不建派生表见 §9.1。
- **不用 `localeCompare`**：它能复现今天的顺序，但要求全局排序，与分片天然冲突。
### 3.8 取数总则：一律分片（重数据与一级都分片）

| 数据 | 现状 | 改成 |
|---|---|---|
| 一级索引行（图组页的图组、图库页的角色） | 全量取回 | **分片**：`ORDER BY <排序键>, id` + 快照边界 |
| 缩略图（封面） | 随行一起取 | **一条按分组取代表图的查询**，只查当前可见分组的 id |
| 二级图片行（带缩略图） | 全量取回 | **一律分片**：图库页 `LIMIT/OFFSET`（表格跳页与平铺加载更多**共用同一套**）；图组页展开面板内按分片 + 虚拟滚动 |
| 查看器载荷 | 全量列表 + 全部缩略图 | 「筛选条件 + 起始 id」，查看器按分片取（**已定：本次做**） |

- **分页机制统一**：不用游标，统一 `LIMIT/OFFSET`（表格要跳页、平铺要「加载更多」，两者用同一套参数）+ **快照边界**（首次查询取一次 `MAX(id)`，之后所有分片都带 `id <= bound`，后台任务写入时不会重复或漏项）。
- **计数**：一级与图库页的图片总数各一条 `COUNT(*)`（表格页码与「共 N 张」用）；筛选条件参与 COUNT，保证页码与分片一致。

### 3.9 代码组织（复用优先）

- 三个文件：偏好读写（`useViewMode` 一类）、切换按钮（一个小 SFC）、平铺容器（网格、展开面板、封面占位、复选框与三态）。
- 两个页面只提供各自的数据与插槽内容；表格分支保留，只换数据来源。

## 5. 风险

| 风险 | 应对 |
|---|---|
| 拼音库对二次元 / 生僻 / 多音字不保证读音正确，顺序可能不合直觉 | 键是派生数据、随时可整表重建（阶段 4）；退化的表现只是顺序不理想，不会崩、不会丢数据；将来留人工覆盖入口 |
| 分片后失去「快照」语义，后台任务写入时翻页可能重复或漏项 | 首次取 `MAX(id)` 作边界 |
| 表格从同步 computed 变成异步查询 | 加载态先不做（记入 §8），但要保证查询可取消 / 过期响应丢弃，避免快速改筛选时错序 |
| 自适应列数 + 行窗口化：列数一变就要重算行数组 | `ResizeObserver` 监听容器宽，列数变化时重建行数组并尽量保持滚动位置 |
| 虚拟滚动与「行下展开整行面板」的布局冲突 | 展开面板当作一种特殊的「行」塞进行数组；二级面板自己再有最大高度与内部窗口化 |
| 选中持久化后，批量操作的范围可能超出当前页 | 批量按钮上显示数量（现有行为），确认对话框里也给出数量（图库页删除已有） |

## 6. 验证方法

1. 切换与记忆：两页各切到平铺 → 刷新 → 仍是平铺；切视图回到第一页 / 顶部。
2. 两级展开：单击展开、再点收起、展开新的自动收起旧的；二级面板有最大高度、内部可滚动加载更多。
3. 分片正确性：图库页翻到最后一页不重不漏，与 `COUNT(*)` 对得上；后台跑一个任务时翻页不出现重复行（快照边界生效）。
4. **大数据量与 DOM**：在一个很大的图组 / 角色上滚到底，DevTools 里确认 DOM 节点数基本恒定、渲染进程不再持有全量缩略图。
5. 选中：翻页 / 改筛选 / 改排序 / 切视图后选中都还在；表格与平铺看到的是同一批 `selectedIds`；图库页卡片三态正确。
6. 查看器接线：图组页点图片 → 打开该图组并定位；图库页点图片 → 打开当前筛选结果并定位；载荷不再包含全量缩略图。
7. 筛选：图库页筛选后为空的分组隐藏、条件一变回第一页、输入不卡；图组页筛选仍作用于图组。
8. 排序：中英文混排下对比新旧顺序（新的分组前缀与拼音正文见 9.2），把差异记录在案。
9. 尺寸扩展：临时把卡片宽改一个值，确认网格列数与窗口化跟着变。

## 9. 实施计划（含排序键前置）

> **这一节是可恢复的进度清单**：每完成一项就把 `[ ]` 改成 `[x]`，并在该项后面补提交号与偏差。上下文被压缩之后，读这一节就能接着干。
> 已定的决策：排序键**每字段一列**（理由见 9.1）；规则见 9.2；列与索引清单见 9.3；阶段见 9.4。

### 9.1 为什么用「每字段一列」而不是一张派生表

1. **一致性风险**：列跟着行生死，删除实体不会留下孤儿键；派生表要「写业务行 + 写键行」两处，删实体还得手动清（本仓库没有外键），漏一处就是静默错序。
2. **改动局部**：8 个字段的写入点全在 `src/main/db.ts` 里（已核实：`addSource` / `insertCharacter` / `renameCharacter` / `insertImageGroup` / `insertImageFiles` / `insertScript` / `renameScript` / `upsertProcessedImage`，共 9 处），grep 得到、评审得过来。
3. **查询更简单**：`ORDER BY c.name_sort, c.id` 直接吃 `(name_sort, id)` 索引，不需要多一次 join，`EXPLAIN` 一眼能读。
4. **派生表的唯一强项用不上**：「以后频繁加可排序字段」才值得为它多引入一个概念与一类同步 bug；我们的可排序字段是**有限且稳定**的 8 个。
5. 代价与对策：加字段要一次 changelog（可接受）；`SELECT *` 会把派生列带进业务对象——在 `shapeRow()` 里**统一剔除 `*Sort` 列**（一处，集中），不改那 14 条 `SELECT *`。

### 9.2 排序规则（sortKey 规范）与可插拔的排序模块

- **实现全在 JS 侧**：拼音读音来自 `pinyin-pro`，分组前缀与逐段规则是我们自己的常量（划分见下方模块）。
- 键 = `<组前缀> + <正文>`，组前缀用可读的 ASCII：

| 前缀 | 归组（按**首字符**判定） | 正文规则 | 模块 |
|---|---|---|---|
| `1\|` | 标点 / 符号 / emoji | 原样小写 | `scripts/symbols.ts` |
| `2\|` | 数字开头 | 数字段零填充到 10 位（自然序：`img2` < `img10`） | `scripts/digits.ts` |
| `3\|` | 汉字开头 | 全拼、小写、无声调、字间空格分隔（`张三` → `3\|zhang san`） | `scripts/han.ts` |
| `4\|` | 拉丁字母开头 | 原样小写 | `scripts/latin.ts` |
| `5\|` | 其他文字（希腊 / 西里尔 / 假名 / 谚文 / 未归类） | 原样小写 | `scripts/other.ts`（兜底） |

- **逐段处理混合名**：汉字段转拼音、数字段零填充、其余段小写原样，段间单个空格：`第2章` → `3\|di 0000000002 zhang`；`Alice 王` → `4\|alice wang`。
- **读不出读音的汉字**退回原字，落在汉字组末尾（读不出就不猜，顺序稳定、可重算）。
- **多音字由 profile 决定**：`sortKeyOf(text, profile)`——`character.name` 用 `han: 'surname'`（人名姓氏模式），其余字段用 `han: 'default'`。只影响顺序，随时可重算。
- **tie-break**：`ORDER BY <列>, id`（全序，分片必需）。
- 实测依据（本机）：**今天界面的混排顺序**是 `符号 → emoji → 数字 → 汉字(组内拼音) → 拉丁 → 其他文字`；纯码点会大小写分裂、汉字乱序、emoji 垫底，所以不能用码点。

**可插拔：按文字系统分模块，加一门文字只加一个文件**

```
src/main/database/sort/
  key.ts        编排：把字符串切成「模块段」，查注册表，拼组前缀与正文
  registry.ts   文字系统 → 模块 的注册表：按字符类分派，第一个匹配者胜
  profile.ts    字段 → profile：文本列 / 键列 / 读音策略（回填与重建按它遍历）
  scripts/
    han.ts      汉字 → pinyin-pro（surname / default 两档）
    latin.ts    拉丁 → 小写原样
    digits.ts   数字 → 零填充
    symbols.ts  标点 / emoji → 原样
    other.ts    兜底：未归类的文字 → 原样
  index.ts      出口：sortKeyOf / rebuild
```

每个模块的契约（很小）：

```ts
interface SortScript {
  /** 组前缀，决定它整体排在哪一组（1| … 5|） */
  group: string;
  /** 这个字符归不归我管；注册表按顺序问，第一个 true 的胜出 */
  matches(char: string): boolean;
  /** 把这一段变成可比较的正文（例：汉字 → 拼音，数字 → 零填充） */
  encode(text: string, profile: SortProfile): string;
}
```

- 日后要支持**日文（假名按五十音序）**：新增 `scripts/kana.ts`（假名 → 罗马字表）并把它插到注册表里 `other.ts` 之前——**调用方、数据列、重建流程都不动**。
- 换拼音词库同理：只动 `scripts/han.ts`（它是唯一 import `pinyin-pro` 的文件）。
- 键是派生数据：规范一变就是一次整表重建（阶段 4 的入口）。

### 9.3 列与索引清单（一次全加，8 列 / 6 表）

| 表 | 新列 | 排序索引 | 写入点 |
|---|---|---|---|
| `source` | `name_sort`、`root_path_sort` | `(name_sort, id)` | `INSERT_SOURCE` / `addSource` |
| `character` | `name_sort` | `(name_sort, id)` ← 图库页默认排序靠它 | `INSERT_CHARACTER` / `insertCharacter`、`RENAME_CHARACTER` / `renameCharacter` |
| `image_group` | `dir_name_sort`、`dir_path_sort` | `(dir_name_sort, id)` | `INSERT_IMAGE_GROUP` / `insertImageGroup` |
| `image_file` | `file_name_sort` | `(file_name_sort, id)` ← 图组页二级的分片顺序 | `INSERT_IMAGE_FILE` / `insertImageFiles` |
| `process_script` | `name_sort` | `(name_sort, id)` | `INSERT_SCRIPT` / `insertScript`、`RENAME_SCRIPT` / `renameScript` |
| `processed_image` | `script_name_sort`（脚本名的副本） | `(script_name_sort, id)` | `INSERT_PROCESSED` / `UPDATE_PROCESSED` / `upsertProcessedImage`、`RENAME_PROCESSED_SCRIPT_NAME` |

- 额外一条索引：`processed_image(selected_file)`——图库页按**文件名**排序时，SQLite 要能从 `image_file(file_name_sort, id)` 方向驱动再探测 `processed_image`，否则会退化成排序或全表扫描。
- 脚本行的键单独一条 `UPDATE`（`insertScript` / `renameScript`）：老库升级途中还没有这些列，那时跳过并记日志，由 1.1.1 的回填补上。
- `SELECT *` 带出的派生列由 `shapeRow()` 统一剔除（见 9.1 第 5 条）。
- 回填：`postups.ts` 里**每个 kind 一遍扫表**算完该表所有列（不要每列扫一遍），幂等、可重复执行；失败随事务回滚。
