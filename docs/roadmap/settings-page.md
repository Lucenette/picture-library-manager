## 1. 背景

1. **现在没有任何设置入口，能调的东西全是常量或环境变量**：日志级别 `PLM_LOG_LEVEL` / `PLM_LOG_LEVEL_EXTERNAL` / `PLM_LOG_LEVEL_SCRIPT`（`src/main/log/logger.ts:98`），日志保留 50 MB / 20 个文件 / 14 天（`logger.ts:28`），相似判定阈值 `SAME_DISTANCE = 3` 与 `SIMILAR_DISTANCE = 10`（`src/main/image/similar.ts:16,19`），整库备份间隔 30 秒（`src/main/database/db.ts:23`）与升级前备份保留 3 份（`src/main/ups/engine.ts` 的 `BACKUP_KEEP`），解码并发与内存预算（`src/main/image/thumbnail-pool.ts`、`src/main/task/runners/scan.ts`）。
2. **一批新需求正在排队，都是「要有个开关，但没地方放」**：打开日志目录 / 收集日志（diagnostics）、默认外部编辑器（open-script-in-editor）、平铺/列表默认视图（view-layouts）、颜色主题（theme）。逐个往现有页面塞，很快就把它们变成杂物间。
3. **环境变量对桌面应用的使用者不成立**：Windows 上要改系统环境变量、打包后没有终端、Mac/Linux 上还得开 shell；要能调就得有一个落盘、可手改、可备份的位置。
4. **用户目录已经分好四份**（`data/` `scripts/` `temp/` `logs/`，见 AGENTS 的数据目录一节），加一份 `settings.yml` 与它们同源：排障、备份、搬家时是同一套东西。
5. **从别的工具迁移过来的人对手改配置有预期**（dsh 就是 `settings.yml`），YAML 允许注释，比 JSON 更适合「人写一次、机器偶尔改」。

## 2. 目标与非目标

**目标**

1. 主窗口有一个「设置」页：分组呈现、逐项可改，改完立即生效或明确提示「需重启」。
2. 设置在 `~/.plmanager/settings.yml`（开发态 `dist/settings.yml`），主进程独占读写；文件坏掉、键缺失、值非法都不影响启动（退回默认值 + 一条 error 日志）。
3. 后续路线图里的开关（主题、默认编辑器、诊断入口、视图默认值）都挂在这一页，不再新开页面。
4. 手改这个文件与在界面里改等价：改完重启或下一次读取生效；未知键保留，手写注释尽量不动。

**非目标**

- 不做多套配置与作用域（没有 workspace 级设置）——一个用户一份；
- 不做在界面里直接编辑 YAML 原文件（界面是表单，文件只是落点）；
- 不做设置的云同步、导入导出（要做另立条目）。

## 3. 设计

### 3.1 文件与读写

- 路径 `join(getUserDir(), 'settings.yml')`（`src/main/paths.ts:15`），与 `data/` `scripts/` `temp/` `logs/` 同级。
- **只有主进程读写**（渲染进程不许碰 fs）；写用 `writeFileAtomic()`（`src/main/script/files.ts` 已有：先写临时文件再改名），避免半截文件把设置写坏。
- 读：启动时读一次进内存，之后以内存为准；改动即整份写回。

### 3.2 YAML 解析器（需要使用者批准加依赖）

- 现在 `package.json` 的 dependencies 里**没有** YAML 解析器；`node_modules/js-yaml` 存在只是 electron-builder 传递带进来的，不能直接 `require`（打包后不保证在，也不是我们的依赖）。
- 三个选项：(a) 明确加 `js-yaml`（成熟、体积小、会丢注释）；(b) 加 `yaml`（能保留注释与格式）；(c) 自己写极简子集（键值 + 一层嵌套）——**不推荐**，手写解析是长期负债。
- 按 AGENTS「不自行安装或卸载依赖」，这条要先由使用者批准再加。

### 3.3 校验、默认值与兼容

- 每个键一个默认值 + 一个校验器；坏值记一条 error 并用默认值，**绝不让设置挡住启动**。
- **未知键保留**：读时留一份原始文档，写回时合并回去——新版本写的键被旧版本打开也不会被抹掉。
- 手写注释能否保留取决于解析器（`js-yaml` 会丢、`yaml` 能留）；这条要在文档里写明，别让「手写的注释被吃掉」变成惊吓。

### 3.4 生效时机（每一项都要标注）

- **立即**：主题、界面类默认值；
- **下一次操作**：默认导出目录、默认外部编辑器；
- **需重启**：日志级别与保留策略、解码并发与内存预算——它们在启动时就被固化了。

### 3.5 启动顺序上的一个硬约束

- `src/main/index.ts:102` 在最顶上就 `setupLogging()`（要能记录「开库失败」「窗口没建起来」），而日志级别现在来自环境变量（`logger.ts:98`）。要把日志级别搬进 `settings.yml`，就得**在配置 log4js 之前读完文件**——那一次读只能是同步的。
- 两条路：一是接受「启动首读同步」（小文件、一次）；二是第一版不让设置页管日志级别，继续用环境变量，设置页只显示「当前值来自环境变量」。

### 3.6 界面与刷新

- 入口：左侧导航的第 7 项（现有 6 项，见 `src/renderer/App.vue` 的 `NAV_ITEMS`），与「任务管理」同属贴底那一组；不放标题栏（标题栏留给拖拽区与系统按钮）。
- 页面按用途分组：日志（级别、保留、打开目录、收集）、界面（主题、默认视图）、脚本（默认外部编辑器）、图库（相似阈值）、高级（并发与内存预算、备份间隔）。每项右边标注当前值来源（默认 / 文件 / 环境变量）。
- 改动推送给所有窗口（`settings:changed`）；需要主进程自己立刻跟上的（窗口底色、系统按钮字形色）由主进程处理。

## 5. 风险

| 风险 | 应对 |
|---|---|
| 坏文件挡住启动 | 解析失败即用默认值 + 一条 error 日志 |
| 手写注释被写回吃掉 | 选能保留注释的解析器，或把这条写成已知代价 |
| 设置项语义分散、生效时机不一致 | 每项必须在文档与界面上标注「立即 / 下次 / 需重启」 |
| 阈值类设置被改坏（相似距离、并发数） | 校验范围；超范围退回默认并记日志 |
| 启动首读同步 IO 与「主进程不许同步 IO」冲突 | 见 §3.5 的两条路 |

## 6. 验证方法

1. 纯逻辑：默认值合并、坏值回退、未知键保留、原子写——用临时目录与假文件在沙箱里跑断言，不需要 Electron。
2. 人工冒烟：改一项立即生效的（主题）、一项需重启的（日志级别）；手改文件后重启；故意写坏文件确认还能启动。
