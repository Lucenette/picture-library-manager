# 视觉素材与 LoRA 训练流水线

**状态**：待评审
**关联**：[headless-server.md](./headless-server.md)（本条目要跑在无头 server 上）、[similar-semantic.md](./similar-semantic.md)（图像向量与自动打标是它的前置）、[settings-page.md](./settings-page.md)（目录与配比参数的落点）

## 1. 背景

1. **来源**：本条目整理自 2026-10 的一次外部讨论，它把「生图工作流里自动搜图 + 自动训 LoRA」逐步细化成一条「素材采集 → 图库 → 自动训练 → 自动验收 → 版本迭代」的完整流水线。本文件是那次讨论的归档与落地化，不是凭空设计。
2. **缺的模块**：现有底座（来源扫描、角色与图片组、任务队列、缩略图与感知哈希、图库与导出、SQLite）覆盖这条流水线的前半段；缺的是全量收藏、一图多版本、分级 / 评分、动态抽样、训练编排与版本管理。
3. **与现有产品语义冲突**：PLManager 现在是「每个图片组选一张 best」，本条目要的是「来者不拒的全量收藏库」。这不是加功能，是**资产模型的重定义**，影响面最大。
4. **分级不是可选项**：成人向内容会污染画风、构图与肢体，占比 20%~40% 就可能让日常图跑偏，占比过半基本让模型变成专用模型；所以必须做分级、配比与参与开关，而不是「角色对了就行」。

## 2. 目标与非目标

**目标**

1. 图库是永久收藏库：来者不拒，每张图保留 `_raw` / `_hd` / `_train` 三个版本。
2. 每张图带两个维度：适龄分级（G / MILD / ADULT）与质量评分（0~10），数据库为主、`meta.json` 随文件、EXIF / XMP 可选。
3. 训练不维护静态数据集：每次训练从全库按「分级配比 + 评分加权」动态抽样，低分过滤、单次去重，训练结束临时集销毁。
4. 训练全自动：数量达标且静默一段时间即触发；已有对应 LoRA 直接复用。
5. 训练完自动验收：抽提示词库试生成 + AI 评测，达标升版，不达标告警回滚并重试。
6. 版本有生命周期：Alpha / Beta / Stable / 归档 + 保护标记 + 过期 + 回收站。
7. 管理面能人工干预：多版本预览、改分级 / 改评分、批量操作、统计、配比模板。

**非目标**

- 不做训练算法本身（调用现成训练框架）；
- 不做云端推理与云端训练；
- 不做对话、思维与记忆，只做「视觉素材与模型」这一段；
- 第一版不做多用户与权限体系。

## 3. 设计

### 3.1 资产模型（最重要的改动）

- 从「图片组选一张」改为「图片资产」：一张图 = 一条资产记录，挂三份文件路径（raw / hd / train）。
- 现有 `processed_image` 保留为「选图结果」，另建资产表承载全量收藏、分级与评分；两者用资产 id 关联。
- 资产入库与图组扫描解耦：扫描仍是「发现文件」，入库流水线才是「生成版本 + 打分 + 分级」。

### 3.2 一图三版本

- 命名：`[角色ID]_[图ID]_raw|hd|train.ext`。
- 目录：`/CharacterLibrary/<角色>/All_Images/<资产ID>/` 下放三个版本与 `meta.json`。
- `_raw` 保留原始文件与 EXIF；`_hd` 是超分 / 降噪后的高清版；`_train` 是统一尺寸、居中裁主体、去水印后的训练专用版。

### 3.3 元数据

- 主存数据库；`meta.json` 随文件携带数据库与 EXIF 放不下的字段（去重哈希、水印检测、姿态分类、打分依据、人工备注、是否参与训练）。
- 可移植副本：优先写 **XMP**（`Rating` 是标准评分字段），自定义字段（`Content_Rating` / `Quality_Score`）能写就写。写 XMP / EXIF 通常需要 exiftool 一类原生工具，与本项目「零原生依赖」的取向冲突，见待决事项 5。

### 3.4 入库流水线

预处理（校验、生成图 ID、存 `_raw`）→ 生成 `_hd` 与 `_train` → 分级（动漫向 NSFW 模型，G / MILD / ADULT）→ 多维评分（画质、构图、特征匹配、瑕疵加权）→ 落库。

### 3.5 动态抽样

- 参数：总抽样数、分级配比、评分权重、低分过滤阈值、去重规则；按模型分支独立配置。
- 执行顺序：读分支配置 → 全库过滤低分 → 按分级分池 → 按比例算每组数量 → 池内按评分加权随机抽取 → 取对应 `_train` 组成临时训练集 → 训练后销毁，原库不动。
- 每次抽样记录**种子与结果**（图片 id、分级分布、分数区间），否则「哪一批素材导致模型变差」无法回溯。

### 3.6 训练触发与编排

「有效图片数达标 + 静默时长」触发。训练任务是长任务，直接复用现有 TaskManager（已有暂停 / 继续 / 重试 / 强制结束），进度与日志按现有任务通道展示。

### 3.7 提示词库与自动验收

- 采集：每次调用该角色生图时的正向提示词 → 脱敏（角色名、身材等词条）→ 去重入库，按角色与分支隔离。
- 验收：训练完抽词批量试生成 → AI 评测（角色匹配、画面完整度、分级倾向）→ 通过则升版，不通过则告警、回滚、调整参数重试。

### 3.8 版本生命周期

Alpha（待测 / 验收失败）/ Beta（验收中）/ Stable（线上）/ Archived（人工保护，永久保留）。保护标记脱离一切自动清理；过期进回收站并定期清空；人工可强制升降。

### 3.9 管理面

多版本预览、分级与评分手动修正、批量改分级 / 改分 / 标记禁止参与、统计面板（各级数量、分数分布、来源统计）、配比模板一键切换。

### 3.10 与外部调用方的关系

对外暴露两类接口：MCP 或 HTTP，供外部调用任务与查询素材、模型版本；`/metrics`，供外部监控。图像向量可作为其中一项查询能力。

## 4. 改动清单

| 位置 | 改动 |
|---|---|
| 数据库 | 新增资产表（全量收藏、三版本、分级、评分）与抽样日志表；`ups/changesets/<版本>/dbups.xml` |
| `src/main/image/` | 新增超分、标准化、分级、评分、抽样模块 |
| `src/main/task/runners/` | 新增「入库处理」「训练」「验收」三类任务 |

| 渲染进程 | 图库页加多版本对比、分级 / 评分编辑、批量操作、统计；训练与版本管理页 |
| 设置 | 训练目录、分级配比模板、评分阈值、ADULT 参与开关 |
| 无头 server | 见 [headless-server.md](./headless-server.md) |

## 5. 风险

| 风险 | 应对 |
|---|---|
| 资产模型重定义影响面大 | 单独大版本；preups 落盘备份；桌面功能不退化 |
| 成人内容污染训练 | 分级 + 配比 + 参与开关；主力分支默认 ADULT = 0 |
| 三份文件占三倍磁盘 | 低分图不保留 `_hd`；过期回收站；后台可配 |
| XMP / EXIF 需要原生工具 | 以数据库 + `meta.json` 为准，XMP 作为可选增强 |
| 讨论假设的子模块本项目没有，范围容易被低估 | 按本条目新增，不假设已有；先做资产模型再看训练 |
| 没有测试框架 | 与 [测试系统](../design/test-system.md) 一起做 |
| 训练与其他 GPU 任务抢同一块显卡 | 训练走现有单并发任务队列；多进程部署时用文件锁或调度错峰 |

## 6. 验证方法

1. 用样例图库（`node scripts/make-fixture.mjs`）跑通：入库 → 生成三版本 → 分级 → 评分 → 抽样。
2. 纯逻辑断言：抽样分布符合配比与权重；低分被过滤；单次不重复。
3. 训练集目录结构能被目标训练框架直接读取。
4. 人工验收：抽词试生成 → 评测 → 版本流转（升版 / 回滚）。
5. 手工冒烟：管理面的多版本预览、改分级 / 改分、批量操作、统计。
