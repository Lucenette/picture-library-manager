# 图标库：用独立 SVG 图标库替换 Element Plus 图标

**状态**：待实施

---

## 1. 背景

1. **图标来源绑死在 Element Plus 上。** 界面图标全部来自 `@element-plus/icons-vue`，它只为 EP 组件设计，
   集合小、风格固定在 EP 一套；想加一个常用图标就得自己画或再引一套。
2. **两套图标混用会不一致。** 临时补图标只能写字面 SVG 或另引一个库，线与圆角风格对不上，同一页出现两种观感。
3. **需要一个能跟主题、又能按需打包的方案。** 图标要跟 `--app-*` 令牌变色（`currentColor`），
   且只把用到的打进包；EP 图标包整体不小，全量引入不值。
4. **现在没有图标的统一入口。** 组件各自 `import { Xxx } from '@element-plus/icons-vue'`，换库要满仓改。

## 2. 目标与非目标

**目标**

1. 全仓不再依赖 `@element-plus/icons-vue`，图标来自一个独立、现代的 SVG 图标库。
2. 图标颜色一律走 `currentColor` / `--app-*` 令牌，跟随系统明暗，组件里不写死色值。
3. 只打包用到的图标，新增图标不改构建配置。
4. 有统一入口：换来源只改一处，不逐个组件改 import。

**非目标**

- 不改图标的视觉尺寸与所在布局；
- 不引入图标字体；
- 不做运行时远程加载或动态图标市场。

## 3. 设计

1. **来源**：优先 Iconify 体系（`unplugin-icons` + `@iconify-json/<set>`）——编译期按需产出单个 SVG，
   集合覆盖广、天然 `currentColor`；备选 `lucide-vue-next`（风格统一、包更小，集合有限）。
2. **入口**：新增 `src/renderer/components/AppIcon.vue`，集中维护「语义名 → 具体图标」的映射，
   组件只引它。换库或换图标集只改这一处。
3. **打包**：走编译期方案，只产出被引用的图标；不整包引入。
4. **主题**：默认 `currentColor`；需要单独着色的位置由 `--app-*` 令牌驱动。

## 4. 改动清单

| 位置 | 改动 |
|---|---|
| **新增** `src/renderer/components/AppIcon.vue` | 图标统一入口：按语义名渲染 SVG，颜色走 `currentColor` |
| `package.json` | 去 `@element-plus/icons-vue`，加图标库依赖（依赖变更须使用者确认后安装） |
| `electron.vite.config.ts` | 用 `unplugin-icons` 时挂插件并限定要用的图标集 |
| `src/renderer/**/*.vue` | 把 `@element-plus/icons-vue` 的引用换成 `AppIcon` |
| `docs/design/`（落地后） | 图标来源与入口的说明 |

## 5. 风险

| 风险 | 应对 |
|---|---|
| 换库后个别图标语义对不上 | 逐文件核对现有图标的用途，宁可用同义图标也不混用两种风格 |
| 编译期插件拖慢构建或影响缓存 | 只挂一个图标集，构建后比对冷/热启动耗时；必要时退回 `@iconify/vue` 运行时按需方案 |
| 再引一棵依赖树 | 只用纯 JS 的图标包，不引原生件 |

## 6. 验证方法

1. `yarn typecheck` / `yarn lint` / `yarn test` 全过；`git grep '@element-plus/icons-vue' -- src` 为空。
2. 人工：四个窗口各看一遍（主窗口、查看器、浮窗、各类对话框），浅色与深色下图标颜色正确、无缺图或方框。
3. 打包后确认图标进了产物，且没有整包图标库的体积。
