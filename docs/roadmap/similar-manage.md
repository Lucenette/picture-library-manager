# 相似图片管理

**状态**：待评审（初稿，方案尚未评审）
**关联**：[task-process.md](./task-process.md)、现有 `SimilarDialog.vue` 与 `main/dialogs/similar.ts`

---

## 1. 背景

1. 相似图识别目前是**纯展示**：窗口按「相同 / 相似」两个页签列出分组，用户查看之后没有任何可执行动作；
2. 识别结果的价值在于**清理重复**：同一张画在多个图片组里各选了一张，应当只保留其中一张；
3. 需要一套"选择保留、删除其余"的流程，且该流程不得误删不可恢复的内容。

## 2. 目标与非目标

**目标**

1. 将展示窗口升级为管理窗口：每组可选择保留哪一个（或哪几个），默认保留第一个；
2. 每组至少保留一个（硬约束），全部满足后才允许提交；
3. 提交时删除未被保留的冗余记录，并同步更新识别结果；
4. 点击图片以内置图片查看器打开**本组的全部图片**。

**非目标**

- 不触碰磁盘上的原始文件；不做自动清理，必须人工确认。

## 3. 设计

### 3.1 选择模型

- 每个分组维护一个选中集合，默认选中第一个成员；
- 每组具有模式：**单选**（默认）或**多选**；
  - 单选：选中互斥，恒满足"至少一个"；
  - 多选：可勾选多个，但不允许取消到 0 个（最后一个不可取消）；
- 顶部汇总：共 N 组、已确认 M 组、将删除 K 条记录；
- 「确认保留」按钮仅在**全部组均满足约束**时可用。

### 3.2 交互

- 单击图片 = **打开查看器**；点击角标或悬浮复选框 = **切换选中**（与系统图库一致，避免误触）；
- 每组提供「保留这个」快捷按钮，等价于单选该张并清除同组其它选中；
- 底部固定操作条：确认保留（主按钮）、重置选择、关闭。

### 3.3 打开查看器

- 点击图片调用现有图片查看器窗口，载荷为该组的全部文件：
  复用 `ViewerPayload` 与 `ViewerFile`，其字段（`filePath`、`fileName`、`fileSize`、`width`、`height`、`thumbnail`）已具备；
- 查看器内可沿用现有键盘与滚轮导航，在本组内切换。

### 3.4 "删除"的语义（关键决策）

删除对象有三种候选：

| 方案 | 动作 | 影响 | 可逆性 |
|---|---|---|---|
| **a（倾向）** | 删除该图片组的 `processed_image` 记录 | 该图片组回到「未选图」，可重新选图 | 重跑选图即可恢复 |
| b | 删除该组的全部 `image_file` 与 `image_group` 记录 | 该组从图库中消失 | 需重扫图库 |
| c | 仅清空该组的 `selected_file` | 介于两者之间 | 重跑选图 |

**磁盘上的原始文件在任何方案下均不改动。**

### 3.5 提交与结果同步

- 提交前弹出原生确认窗口，写明「将删除 N 条记录、保留 M 条」，并注明不删除磁盘文件；
- 单个事务内完成：删除未保留的记录 → 更新 `similar_member` 与 `similar_group`（或整批重写）→ 刷新窗口；
- 识别按组比对，移除某个组不影响其余组之间的相似关系。

### 3.6 撤销

- 首版不提供应用内撤销，依赖数据库 `.bak` 与提交前的确认窗口；
- 可选：软删除（写入暂存表，窗口内提供「撤销本次」）。

## 5. 风险

1. **误删**：删除数据库记录不可逆 → 强制确认窗口、文案明确、事务包裹、依赖 `.bak`；
2. 识别结果与库状态可能不一致（用户已手工删过图片）→ 提交时校验成员是否仍存在，不存在则跳过；
3. 单个分组可能包含十余个成员 → 选择状态统一用 `Map<groupId, Set<filePath>>` 表达；
4. 与管理窗口的关系：识别是任务、管理是窗口，两者通过结果表解耦，不直接通信。

## 6. 验证方法

1. 默认状态下每组选中第一个，「确认保留」可用；
2. 多选模式尝试取消最后一个 → 不允许；
3. 提交后未保留记录从库中消失、保留记录仍在，磁盘文件未变；
4. 提交后窗口刷新，已处理的组不再出现（或标记为已处理）；
5. 点击图片打开内置查看器，可浏览本组全部图片。
