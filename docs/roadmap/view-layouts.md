# 平铺视图

**状态**：待评审（初稿，方案尚未评审）
**关联**：图库页的既有卡片式展示、[ARCHITECTURE.md](../ARCHITECTURE.md)

---

## 1. 背景

1. 图库页与角色页目前只有表格视图：一屏内的信息密度低，不适配"看图挑选内容"的场景；
2. 图库页（`LibraryPage`）已经是"缩略图在上、基础信息在下"的形态，观感与交互已经过验证；
3. 需求是在**图库页**与**角色页**提供同样的平铺展示，缩略图在上、标题与基础信息在下。

## 2. 目标与非目标

**目标**

1. 两个页面各提供「列表 / 平铺」两种视图，可切换并记住上次选择；
2. 平铺项呈现缩略图与基础信息，操作入口仍然可达；
3. 现有筛选、排序、分页与批量操作在两种视图下行为一致。

**非目标**

- 不改动数据模型；不重做现有表格视图；首版不引入虚拟滚动。

## 3. 设计

### 3.1 视图切换

- 工具条右侧增加图标切换（列表 / 平铺），沿用 Element Plus 图标；
- 选择写入 `localStorage`（键如 `view-mode:source`、`view-mode:character`）。
  该偏好属于纯界面状态，不写入数据库；若将来需要多窗口共享再考虑设置表。

### 3.2 平铺项的内容

| 位置 | 图库页 | 角色页 |
|---|---|---|
| 封面 | 该图库的代表图（见 3.3） | 该角色的代表图 |
| 主标题 | 图库名称 | 角色名 |
| 次信息 | 根路径（省略号截断 + `title`） | 所属图库 |
| 第三行 | 最近扫描时间 | 图片组数量 |
| 操作 | 扫描 / 清理 / 删除 | 查看 / 删除 |

### 3.3 代表图的来源

图库与角色本身没有缩略图字段，需要一次查询取"每个图库或角色的第一张图"的缩略图：

- 新增只读查询，按图库或角色分组取 `image_file.thumbnail` 一行
  （分组取最小值，或在 SQL 中使用窗口函数），**不得逐行查询**；
- 缩略图已是 WebP 字节，经现有 `shapeRow` 处理即为 data URL，可直接用于 `<img>`；
- 角色页可取该角色第一个图片组的第一张图；图库页同理取第一个角色的第一个组。

### 3.4 分页与性能

- 平铺沿用现有分页器，每页数量沿用 10 / 20 / 50 / 100；
- 缩略图取自数据库行，不额外读盘；一页 100 张约 250KB，可接受；
- 单页数量继续增大时再评估虚拟滚动。

### 3.5 选择与批量操作

- 平铺项支持与表格一致的多选（单击切换选中）；
- 选中数量与批量按钮（删除选中、导出）沿用现有逻辑；
- 键盘可达性不在首版范围。

## 4. 改动清单

| 位置 | 改动 |
|---|---|
| `src/renderer/components/` | 新增平铺容器组件（封面、标题、附加信息、选中态、悬停操作） |
| `SourcePage.vue` / `CharacterPage.vue` | 视图切换、平铺渲染、选中状态与现有工具栏联动 |
| `src/main/database/`（`db.ts` + `sql.ts` + `changesets/`）` | 新增「按图库或角色取代表缩略图」的查询 |
| `common/types.ts` | 按需补充返回行类型 |

## 5. 风险

1. 代表图若逐行查询会退化为 N 次查询 → 必须单条分组查询；
2. 平铺项内既有整项点击（选中）又有操作按钮，事件会冲突 → 明确点击区域；
3. 视图偏好存放位置将来若改为数据库，需要迁移 → 首版用 `localStorage` 并在文档中写明；
4. 表格与平铺两套渲染会重复处理空态与加载态 → 抽出公共片段。

## 6. 验证方法

1. 两页在两种视图间切换，刷新后保持上次选择；
2. 平铺项显示的封面、标题与基础信息与表格中同一行一致；
3. 筛选、排序、分页在平铺下同样生效；
4. 选中与批量删除、导出在平铺下与表格行为一致；
5. 数据量较大时（例如 50 个图库、数千角色）首屏渲染时间可接受。
