**关联**：[ARCHITECTURE.md](../ARCHITECTURE.md)、[settings-page.md](./settings-page.md)（视图偏好将来从这里迁进设置）

## 1. 背景

1. **两个页面只有分页表格，看图挑选不趁手**：图组管理（`ProcessPage.vue`）一屏几十行文字看不到图；图库（`LibraryPage.vue`）虽有 90px 预览列，但整体按表格排，挑图要来回扫行。
2. **平铺不是「换个样式的表格」，而是相册式的两级结构**：一级看分组、点开看这个分组里的图。两页的「分组」含义不同——图组页的分组是图组本身，图库页的分组是角色（见 3.1）。
3. **图库页的封面现成**：每行都带 `selectedFileThumbnail`（`image_file.thumbnail` 的 BLOB 经 `shapeRow` 转成 data URL）。**图组页没有封面**，要么占位、要么按组取一张代表图——取代表图必须是**一条分组查询**，不能逐行查。
4. **数据量可以很大，所以平铺不分页**：沿用表格的分页会把「相册」切碎；浏览器与手机相册都是滚到底。因此平铺靠**懒加载 + 虚拟滚动**支撑，二级图片展开时才取。
5. **原稿写的页面不对**：本路线图第一稿按「来源页 + 角色页」写（还把来源页称作「图库页」），与实际要做的图组页 + 图库页不是同一对；形态也从「平铺项列表」改成了相册式两级结构（见 1.1）。

## 2. 目标与非目标

**目标**

1. 两个页面保留现有的**分页表格**，并在**页脚左侧**提供一个图标按钮，在「列表 / 平铺」之间切换（只有两个视图，一个按钮即可，像操作系统的文件管理器），选择要记住。
2. 平铺是相册式两级结构：一级是分组卡片（图组页＝图组，图库页＝角色），**单击卡片在它所在行的下方展开**该分组的图片；再点收起。
3. 平铺**不分页**：用懒加载 + 虚拟滚动支撑大数据量；表格视图的分页行为保持不变。
4. 平铺项尺寸固定：封面用现有的缩略图尺寸 100×100（`THUMBNAIL_SIZE`），首版不提供调整。
5. 没有封面时先用占位图标；封面的统一视觉（例如多张叠放）另作安排（见 §8）。

**非目标**

- 不改数据模型；不重做现有表格视图；
- 首版不做封面叠放、不做平铺项尺寸调节、不做键盘可达性与辅助技术适配；
- 不把视图偏好写进数据库（放 `localStorage`，将来迁进设置页）。

## 3. 设计

### 3.1 两级结构与两页的分组含义

| 页面 | 一级＝分组 | 二级＝展开面板里的图片 |
|---|---|---|
| 图组管理（`ProcessPage`） | 图组（现在表格的每一行） | 该图组的图片文件（`getImageFilesByGroup`） |
| 图库（`LibraryPage`） | **角色**（把现在的行按 `characterName` 归拢） | 该角色下的**已选定图**（每个图组一张） |

- 展开面板插在「该卡片所在那一行」的下方、整行宽；一级网格用它上方的卡片排版不变。
- 同时允许展开几个、展开面板里图片的勾选与单击如何分工、批量操作以什么为单位——都在 §7 继续讨论。

### 3.2 懒加载与虚拟滚动

- **平铺不分页**：一级卡片与二级图片共用一个滚动容器，只挂载视口附近的项；滚动到底再取后面的数据。
- **二级按需取**：只有展开某个分组时才取该组的图片（或按分片取），不预先全量拉。
- 请求要**去重 + 过期响应丢弃**（快速滚动与快速展开时会并发）。
- 具体实现（自己写窗口化 + `IntersectionObserver`，还是引入现成依赖）在 §7 定；**引入依赖需要使用者先批准**（AGENTS：不自行增删依赖）。
- **两页的「懒」不是一回事**：图库页的数据其实已经全量在渲染进程里（`getAllProcessedImages()` 一次取回全部行的缩略图 data URL，本次实测 4175 行的查询 + 形状化约 77ms），那里要解决的是 **DOM 窗口化**；图组页的二级必须**数据懒加载**（展开某个分组时才取该组的图片文件）。

### 3.3 封面

- 尺寸：100×100（与缩略图常量一致），`object-fit: cover`。
- 图库页用行里现成的 `selectedFileThumbnail`；图组页需要一条**按组取代表缩略图**的分组查询（按分片 id 列表查，不逐行查）。
- 没有缩略图时先用占位图标（统一视觉见 §8）。

### 3.4 视图切换按钮

- 位置：**页脚那一行的左下角**（现在分页器占右下、左侧空着），一个图标按钮，点一下在两种视图之间切换；tooltip 显示「切到平铺 / 切到列表」。
- 表格视图下分页器照旧在右下；**平铺视图下隐藏分页器**（它不分页），按钮仍在左下角。
- 偏好存 `localStorage`：`view-mode:process` / `view-mode:library`；读不到就退回列表。

### 3.5 与图片查看器的接线（沿用现有入口）

- **图组页**：点展开面板里的图片 → 图片查看器打开**该图组的图片**并定位到这一张；分组上的「打开全部」走同一个列表。
- **图库页**：点图片 → 图片查看器打开**全部图片**（当前筛选结果）并定位到这一张。
- 图组页原先的「查看文件 / 手动确认选图」对话框在新形态里的入口，见 §7 第 4 条。

### 3.6 代码组织

- 能复用就复用：偏好读写（`useViewMode` 一类）、切换按钮（一个小 SFC）、平铺容器（网格、展开面板、占位封面）——具体拆成几个文件等交互定稿后再定（§7 第 8 条）。
- 两页的表格分支不动，只加「另一条渲染分支」。

## 5. 风险

| 风险 | 应对 |
|---|---|
| 虚拟滚动与「行下展开整行面板」的布局冲突（网格里要插入跨列面板） | 自写窗口化时把展开面板当成一个特殊项处理；实现方式在 §7 定 |
| 展开才取二级数据 → 并发请求乱序 | 请求去重 + 过期响应丢弃 |
| 图组页封面逐行查退化成 N 次查询 | 只允许按分片 id 列表的分组查询，代码注释写明理由 |
| 两种视图的选中行为不一致 | 表格用 `el-table` 的选中语义，平铺主动对齐（规则在 §7 定） |
| 平铺不分页后的首屏与滚动性能 | 虚拟滚动 + 懒加载；把「每页 100 项」换成一个合理的视口窗口 |

## 6. 验证方法

1. 切换与记忆：两页各切到平铺 → 刷新 → 仍是平铺；再切回列表同理。
2. 两级展开：单击卡片在它所在行下方展开、再点收起；展开内容与该分组的图片一致。
3. 大数据量：在一个图片很多的图组 / 角色上滚到底，确认是懒加载、内存与滚动都还能用。
4. 查看器接线：图组页点图片 → 打开该图组并定位；图库页点图片 → 打开全部图片并定位。
5. 筛选：表格里的筛选在平铺下仍然生效（语义见 §7 第 6 条）。

## 7. 待续讨论（近期要定，定了才能动手）

每一条都附上**当前倾向**（尚未确认，评审时逐条过）：

| # | 事项 | 当前倾向 |
|---|---|---|
| 1 | 单击 / 双击 / 选中的分工 | **放弃双击**：展开 / 收起占单击；左上角复选框＝选中；「在查看器中打开整个分组」用卡片右下角的图标按钮 + 右键菜单项。原定「单击展开 + 双击打开」会打架——第一次单击已经把面板展开，双击只能靠延迟 250ms 判定，手感明显变钝；而打开整组是低频动作，给它一个看得见的按钮更好 |
| 2 | 展开面板里图片的勾选与单击 | 单击＝打开查看器（已定）；勾选框**常显**（未选半透明、选中实心），不做「悬停才出现」——悬停在误触与触屏上不好用，批量操作也需要可发现 |
| 3 | 批量操作的单位 | 图组页：只在一级卡片上勾选（单位＝图组），展开面板不给复选框；图库页：只在二级图片上勾选（单位＝图片），展开面板里给「全选本组」；卡片（角色）不参与选择。两页的批量按钮一行都不用改 |
| 4 | 图组页「查看文件 / 手动确认」的入口 | 保留在**卡片操作区**（查看文件 / 排除·恢复），展开面板只负责看与多选——既有的手动确认链路零改动 |
| 5 | 同时展开几个 | **一次一个**：虚拟滚动下多个展开会让行高与位置漂移成倍复杂；展开新的时自动收起旧的 |
| 6 | 筛选 / 排序在新结构下的语义 | 筛选继续作用于图片（「文件名 / 脚本」命中后整张角色卡片为空则不显示）；平铺一级**固定按角色名 / 图组名排序**，忽略表格的列排序（平铺没有表头，不存在排序状态对不上） |
| 7 | 虚拟滚动的实现 | **自己写行窗口化，不引依赖**：卡片尺寸固定，可以按列切成行数组，展开面板当作一种特殊的「行」；现成的虚拟列表组件基本都假设等高一维列表，硬套跨列展开面板更麻烦 |
| 8 | 代码组织 | 复用优先：偏好读写、切换按钮、平铺容器各一个文件（见 §3.6） |
