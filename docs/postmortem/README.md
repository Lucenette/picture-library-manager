# 事故复盘

坏的东西走到了不该到的地方（真实使用者、已合并的 PR、一次发布），而值得写的不是那行修复，是**为什么我们的流程放它过去**。

## 什么时候写

同时满足三条才写：**机制不直观**（重来一遍也要费劲推），**系统性**（漏过去的原因是测试、工具或约定的缺口，不是一次笔误），**重新发现的代价高**。为它补上的守卫（用例、`AGENTS.md` 条目、设计说明）在文末列出并链接。

## 怎么写

开头必须有**执行摘要**：一段话讲清坏在哪、根因、为什么漏过去、留下了什么教训；之后按「现象 / 影响 / 时间线 / 根因 / 补上的守卫 / 教训」展开。

事故复盘是唯一允许写「战斗叙事」的层级。别处（[design/](../design/README.md)、提交信息）只写结论与不变量。
