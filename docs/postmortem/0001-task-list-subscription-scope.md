# 事故 0001：切走页面后任务列表不再刷新

## 执行摘要

任务列表是模块级单例，订阅却挂在**第一个调用它的页面**上：页面一卸载就注销，而「已经订过」的守卫挡住了第二次订阅。于是切到「任务」页之后列表停在最后一帧。同一个提交里还带出第二个缺陷——页面把「整张列表」的推送当成单条任务来判，条件永远不成立。修法是把订阅收回模块，页面按 id 在列表里找自己那条；两条都写进了 [AGENTS.md](../../AGENTS.md) 第 7 节。

## 现象

一次实测 299 ms 就跑完的识图任务，在「任务」页显示成「进行中 5%、耗时 18s」；主进程的 `root.log` 与 `task` 表都记着它已经完成。切回「图库」页也不恢复，只有重启应用才刷新。

## 影响

任务页对已完成的任务持续显示进行中；导出与选图结束后列表也不更新。使用者会以为任务卡住，进而重复提交或强杀应用——而任务其实早已结束。

## 根因

两条缺陷叠加，任一条单独存在都会让列表静默停在旧数据：

1. **订阅的生命周期短于状态的生命周期。** 列表是模块级单例（谁都能读、只订一次），监听器却挂在第一个调用 `useTasks()` 的页面（通常是「图库」页）上；页面卸载即注销，而 `subscribed` 守卫认定「已经订过」，不会再订第二次。此后再没有事件进来。
2. **推送载荷的语义被写错。** `task:changed` 推的是**整张列表**，`LibraryPage.vue` 与 `ProcessPage.vue` 却按单条任务判断；条件永远不成立，导出与选图结束后从不刷新。

## 补上的守卫

- `useTasks.ts` 的订阅改挂模块（`ipcRenderer.on` + `subscribed` 守卫，只订一次），不随页面卸载。
- 页面订阅 `task:changed` 时按 `watchedXxxTaskId` 在整张列表里找自己那条。
- [AGENTS.md](../../AGENTS.md) 第 7 节写明这两条：列表订阅必须挂模块；页面收到的是整张列表。

## 教训

- **状态的作用域决定订阅的作用域。** 模块级单例配页面级监听，是注定要断的组合。
- **推送的契约要写死在名字与文档里。** `task:changed` 携带整张列表；把它当成单条，错误会安静地不触发，比抛错更难查。
- **「防重复」的守卫要先说清所有权。** `subscribed` 本身没错，错在没写清订阅归谁；它在正确的场景里挡住了正确的事。
