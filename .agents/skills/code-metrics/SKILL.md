# 代码量统计

## Summary

这份 skill 固定代码量统计的**口径**与**输出形态**。数字本身好拿，容易出问题的是口径漂移：
只数 git 索引还是遍历文件系统、`dist/` 算不算、`--root` 指到哪一层、扩展名集合包含哪几个——
任何一处不同，两次统计就不可比。所以顺序固定为：**先固定范围 → 跑脚本 → 读数字 → 出报告**。

它只回答**规模与结构**的问题（多大、怎么分布）。项目健康度、测试、依赖、协作基建都推不出自代码量，
不属于这里；运行时表现要靠测试与冒烟，见 [AGENTS.md](../../../AGENTS.md)「改完必须自检」。

## 什么时候用

用：

- 使用者问「统计代码量」「这个项目多大」「哪个模块最大」；
- 写文档、路线图或报告需要引用行数；
- 判断某个文件是不是已经过大、拆分粒度是否合理。

不用：

- **判断代码质量或项目健康度**——行数不是质量，10k 行的认真项目强过 100k 行的失修项目；
  测试、CI、依赖、贡献流程这些都要另外查，跟行数没有推导关系；
- **判断运行时表现**——性能与功能要跑测试、跑冒烟；
- **衡量工作量**——重构掉的代码和多写的代码在行数上无法区分。

## 统计前先确认工作区

统计范围默认是**文件系统**，不是 git 索引。跑之前定下三件事并记下来，报告里要写：

1. `git status --porcelain` —— 有没有未提交改动；不干净就在报告里注明「含未提交改动」。
2. `git rev-parse --short HEAD` —— 记下提交号，数字才对得上。
3. 统计根与扩展名集合（`src/` 之外按它判断）—— 默认仓库根与 `.ts .vue .js .mjs .cjs .css .html`；
   带 `--root` 或 `--ext` 时必须写明，否则与其它统计不可比。

## 跑统计

脚本零依赖、只读，不修改任何文件：

```bash
node .agents/skills/code-metrics/scripts/count-lines.mjs
node .agents/skills/code-metrics/scripts/count-lines.mjs --json
node .agents/skills/code-metrics/scripts/count-lines.mjs --top 20 --depth 2
node .agents/skills/code-metrics/scripts/count-lines.mjs --root src --ext .ts,.vue
```

| 选项 | 作用 | 默认 |
|---|---|---|
| `--root <目录>` | 统计根 | 仓库根（由脚本位置推导） |
| `--ext <列表>` | 覆盖 `src/` 之外判为代码的扩展名，逗号分隔 | `.ts .vue .js .mjs .cjs .css .html` |
| `--top <n>` | 单文件排行取前 n 名 | 15 |
| `--depth <n>` | 目录聚合深度 | 3 |
| `--json` | 输出 JSON 而不是文字报告 | 关 |
| `-h` / `--help` | 帮助 | — |

脚本跳过 `.git` / `node_modules` / `dist` / `out` / `.idea` / `.vscode` / `coverage` / `.cache`；
前 8000 字节含 NUL 的文件按二进制跳过。

**代码的判定**：`src/` 下的一切（二进制除外）都算代码，**不论扩展名**——`src/main/ups/changesets/**/dbups.xml`
是建表 SQL 的版本化正文，属于代码；`src/` 之外按扩展名判断（默认 `.ts .vue .js .mjs .cjs .css .html`）。
输出四段：代码合计与按扩展名、按目录、单文件 Top、文件行数分布，外加非代码扩展名的行数。

## 读数字

三条最容易出错的，展开见 [references/interpretation.md](./references/interpretation.md)：

- **对规模档位用代码行，不要用总行数**——总行数被空行与注释撑起来，跨项目不可比。
- **平均值会被超大文件拉走**，判断拆分粒度要看文件行数分布与单文件 Top；行数大的文件还要看它是以逻辑、数据常量还是模板为主。
- **注释率是行首启发式**（误差量级 ±2%），不要拿它做阈值判断；`.vue` 的代码行含模板与样式，不能与 `.ts` 直接比。

## 出报告

照 [assets/report-template.md](./assets/report-template.md) 的骨架填。模板里的 `<尖括号>` 是待填项，
交付前必须逐个替换成实测值，或者连同所在整行一起删掉——**不留占位符**。
报告只谈规模与结构，不要顺手写质量结论。

## 交稿前自检

- [ ] 报告里写明了统计范围：统计根、HEAD、工作区是否干净、扩展名集合
- [ ] 每个数字都能对上**当次**脚本运行，没有沿用上一次统计或旧文档的数字
- [ ] 单文件 Top 的备注列填了（逻辑 / 数据常量 / 模板）
- [ ] 「本次未覆盖的部分」没有空着
- [ ] 交付前重跑一次脚本——你这一轮自己新增的文件也会被算进去，数字会变
- [ ] 如果改了脚本、模板或本文件，跑 `node scripts/check-docs.mjs` 确认文档与 skill 检查仍通过
