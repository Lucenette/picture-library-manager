# 模板：设计说明

用于 `docs/design/<子系统>.md`——已经落地的子系统。参考
[window-management.md](../../../../docs/design/window-management.md)（现行架构）与
[db-migration.md](../../../../docs/design/db-migration.md)（由路线图迁入）。

与路线图方案的区别只有三点：状态行不同；必须在背景后保留 `### 1.1 修改历史`；正文用现在时陈述既成事实，
不再出现「将要」「计划」。文件本身由路线图 `git mv` 而来，不在这里新写。

## 骨架

```markdown
# <子系统名>

**状态**：现行架构
**最后更新**：<YYYY-MM-DD>

---

## 1. 背景

<这份说明要解释的问题：当初是什么逼出了现在这套设计。>

### 1.1 修改历史

记录本文档的修订。

| 日期 | 变更 | 原因 |
|---|---|---|
| <YYYY-MM-DD> | 首次定稿 | — |

---

## 2. <结构或机制>

<先说清这套东西由哪几块组成、各自职责是什么。>

## 3. <关键机制>

## N-1. 改动时的检查点

<改这块代码前必须确认的不变量；写「碰 X 之前先看 Y」这类可直接执行的提醒。>

## N. 已知取舍

| 取舍 | 代价 |
|---|---|
```

## 规则

- 章节标题直接说内容（「成本模型：一个窗口 = 一个渲染进程」），不要用「设计」「实现」这类空标题。
- 正文写现在时；历史只留在 `### 1.1 修改历史` 那张表里。
- 不引用路线图文件；需要指别的子系统时给相对链接。
- 「已知取舍」写清代价，不写辩解。
